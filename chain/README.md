# chain

Foundry project for Hyvo's contracts. It currently holds the **test assets** that the engine deploys
into each job's anvil world. `HyvoOracle` and `PaymentRouter` (Phase 3) will sit
in `src/` next to them.

The test assets are for local anvil worlds only. Do not deploy them to a real network.

## Requirements

- Foundry 1.7.1 (`forge`, `anvil`, `cast`), the version this project is built and tested with.
- Node 22 or newer for the export script (plain ESM, no dependencies).
- Dependencies are git submodules under `lib/`, pinned in `foundry.lock`:
  forge-std `v1.17.0` and OpenZeppelin Contracts `v5.7.0`. After cloning the repo, run
  `git submodule update --init --recursive` from the repo root.

Compiler settings (`foundry.toml`): solc 0.8.28, optimizer on with 200 runs, `evm_version = "shanghai"`
so the bytecode carries no Cancun-only opcodes.

## Build, test, export

```sh
cd chain
forge build
forge test                          # unit, fuzz (1000 runs) and invariant tests, about 15 s
node scripts/export-artifacts.mjs   # writes artifacts/*.json from out/
```

After changing a contract, run all three and commit the regenerated `artifacts/*.json`.

## Test assets (`src/test-assets/`)

| Contract | Purpose |
|---|---|
| `TestToken` | ERC-20 with 18 decimals and `Ownable`; the owner mints agent balances. |
| `TestWETH` | WETH9-compatible wrapped ether: `deposit`, `withdraw`, and `receive` wraps plain transfers. |
| `HyvoV2Pair` | Uniswap-V2-style constant-product pair with a fee fixed per pair (0 to 1000 bps). Its LP token is "Hyvo V2 LP" (`HYVO-V2-LP`). |
| `HyvoV2Router` | Single-hop ETH to token and token to ETH swaps, quotes and ETH liquidity, through one pair that contains WETH. |

Constructors, in deployment order for one world:

1. `TestWETH()`
2. `TestToken(string name_, string symbol_, address owner_)`
3. `HyvoV2Pair(address tokenA, address tokenB, uint16 feeBps_)`: sorts the tokens so `token0 < token1`.
4. `HyvoV2Router(address weth_)`

Then mint tokens to the liquidity provider, approve the router and call
`addLiquidityETH(pair, amountToken, to)` with the ETH side as `msg.value`.

### Swap math

Every router swap outputs exactly

```
amountInWithFee = amountIn * (10000 - feeBps)
amountOut       = amountInWithFee * reserveOut / (reserveIn * 10000 + amountInWithFee)   // integer division
```

with `reserveIn`/`reserveOut` taken from `getReserves()` before the swap and `feeBps` from the pair. The
engine replays recorded swaps with this formula. The pair's K check
(`(balance0 * 10000 - amount0In * feeBps) * (balance1 * 10000 - amount1In * feeBps) >= reserve0 * reserve1 * 10000^2`)
accepts this output and refuses one unit more, which the fuzz tests check. Reference vectors (also in
`test/test-assets/HyvoV2Router.t.sol`):

| amountIn | reserveIn | reserveOut | feeBps | amountOut |
|---|---|---|---|---|
| 1e18 | 100e18 | 1,000,000e18 | 30 | 9871580343970612988504 |
| 1e18 | 100e18 | 1,000,000e18 | 0 | 9900990099009900990099 |
| 1e18 | 100e18 | 1,000,000e18 | 1000 | 8919722497522299306243 |
| 10,000e18 | 1,000,000e18 | 100e18 | 30 | 987158034397061298 |

### Differences from Uniswap V2

- The fee is a constructor parameter in basis points instead of a fixed 0.30%.
- The first `MINIMUM_LIQUIDITY` (1000) LP shares are locked at `0x000000000000000000000000000000000000dEaD`,
  because OpenZeppelin's ERC20 cannot mint to the zero address.
- No factory, flash-swap callback (`swap` has no `data` argument), price accumulators, protocol fee or `skim`.
- `addLiquidityETH` deposits the amounts as given, with no ratio matching or refund: use it to seed a
  pool, or pass amounts at the current pool ratio (any excess stays in the pool).
- Errors are custom errors, listed in each contract.

## Artifacts

`artifacts/<Name>.json` holds `{ "contractName", "abi", "bytecode" }` for `TestToken`, `TestWETH`,
`HyvoV2Pair` and `HyvoV2Router`, where `bytecode` is the 0x-prefixed creation code. The files are
generated by `scripts/export-artifacts.mjs` from `out/<Name>.sol/<Name>.json` and are committed.

## Probes (`src/probes/`)

Read-only contracts that are **never deployed**. A program places their runtime code at a throwaway address
inside one `eth_call` (a state override, with made-up ETH), so they run against the real chain and nothing is
signed or broadcast.

- **`SellCheck`**: Hyvo Check's exit simulation (`packages/check`). One call buys a token with ETH through one
  venue (a Uniswap-V2-style Router02, Uniswap V3 through SwapRouter02 and QuoterV2, a Uniswap V4 pool straight
  through the PoolManager, or a Pons v2 bonding curve), sends a tenth of what arrived to a fresh address, sells the
  rest back, and returns what each step promised (the venue's own math, after its published fees) and what
  arrived, with revert data when a step fails. A hostile token cannot revert the probe through a malformed return
  value or a shrinking balance.

`test/probes/` runs it, placed with `vm.etch` at the address the driver uses, against a plain, a 5%-taxed and a
sell-blocking token on a Router02-style mock over `HyvoV2Pair`, and against a Pons-style curve with fee, creator
tax and snipe tax. After changing it:

```sh
forge build && forge test --match-path "test/probes/*" && node scripts/export-probe.mjs
```

`export-probe.mjs` writes `packages/check/src/probe/sellcheck.json` (ABI, runtime bytecode, compiler settings and
the source's SHA-256); `packages/check`'s tests fail when that file no longer matches the source or forge's build.

## Layout

```
src/test-assets/      test assets deployed into anvil worlds
src/probes/           read-only probes, never deployed (SellCheck)
test/test-assets/     unit, fuzz and invariant tests; utils/ holds the fixture, mocks and the invariant handler
test/probes/          the probe's tests and their mocks
scripts/              export-artifacts.mjs, export-probe.mjs
artifacts/            exported ABI + bytecode (committed)
lib/                  forge-std, openzeppelin-contracts (git submodules)
```

## Production contracts (Robinhood Chain)

Both hold no funds, are not upgradeable, make no arbitrary calls and are built on OpenZeppelin v5.

- **`HyvoOracle`**: `commit(runId, reportHash, scenarioHash, resolvesAt)` and `resolve(runId, outcomeHash,
  outcomeURI)` by the attester (the API Worker's key); `getCommit(runId)`; the owner (a Safe, two-step
  ownership) rotates the attester with `setAttester`. A run id commits once; `resolve` needs a `resolvesAt` that
  has passed. `runId` is the ULID's 128 bits in the low 16 bytes (docs/RUN_FORMAT.md).
- **`PaymentRouter`**: `pay(orderId, token, amount)` moves the payer's tokens straight to the treasury in the same
  call and emits `Paid`. Only owner-allowed tokens (USDG, later the Hyvo token); each order id once; tokens that
  deliver less than `amount` are refused, so `Paid.amount` is what the treasury received. The router's own
  balance is always zero (invariant test).

### Checks before mainnet (spec §7.3)

| Check | Command | Result |
|---|---|---|
| unit, fuzz, invariant tests | `forge test` | 169 passing |
| coverage of both contracts | `forge coverage --report summary --no-match-coverage "(test\|script)/" --no-match-contract Invariant` | 100% lines, statements, branches, functions |
| Slither (no medium or higher) | `python -m slither .` with the uv tool env (`slither.config.json`) | 1 low: `block-timestamp` in `resolve` |

The low finding is by design: `resolvesAt` is a date, and a few seconds of sequencer timestamp drift cannot change
a resolution measured in days. On Windows, call Slither through its Python
(`%APPDATA%\uv\tools\slither-analyzer\Scripts\python.exe -m slither .`) if Application Control blocks the
`slither.exe` shim.

### Deploying

```
HYVO_OWNER=<Safe> HYVO_ATTESTER=<attester address> HYVO_TREASURY=<treasury> \
USDG_ADDRESS=0x5fc5360D0400a0Fd4f2af552ADD042D716F1d168 \
forge script script/DeployHyvo.s.sol --rpc-url $RH_RPC_URL --broadcast --account <deployer>
```

The script writes `deployments/<chainId>.json` (committed for mainnet; `local-*.json` and `test-*.json` are
ignored). The router's ownership moves to the Safe in two steps: the Safe must call `acceptOwnership()`.
Mainnet deployment is a founder action (keys and ETH; docs/OPEN_ITEMS.md item 12).
